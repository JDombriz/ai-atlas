# Etapa 1 — Uso profesional


<img src="../../assets/bandas/banda-e1-indice-es.svg" alt="Etapa 1 · Uso profesional" width="560">
> Versión en inglés: [`README.en.md`](README.en.md), traducción de esta revisión.

> **Objetivo:** trabajar con modelos como herramienta diaria, con criterio para elegirlos, para darles contexto y para saber lo que cuesta cada uso.

La Etapa 0 enseñó de qué se habla cuando se habla de inteligencia artificial y, sobre todo, cuándo no hace falta. Esta etapa responde a la pregunta siguiente, que es la que llega el lunes por la mañana: **con seis modelos disponibles y precios que se diferencian en cien veces, ¿cuál se usa para esto, qué se le da y cuánto va a costar**.

No se aprende aquí a construir sistemas. Se aprende a usar bien una herramienta que ya está instalada, que rara vez se usa bien y que se factura por unidades.

## Al cerrar esta etapa, serás capaz de

- Elegir modelo para una tarea concreta y defender la elección con una prueba propia, no con una tabla de clasificaciones.
- Escribir una instrucción reutilizable: con su contexto, su formato de salida y un criterio explícito de «esto está bien».
- Decidir qué información se le da al modelo, en qué orden y qué se deja fuera a propósito.
- Estimar el coste de un uso repetido antes de prometerlo, incluida la letra pequeña que lo dobla.
- Reconocer cuándo el modelo no es la herramienta y el trabajo se hace de otra manera.

## Prerrequisito

La Etapa 0 cerrada, con su práctica entregada. De la materia no se presupone nada más de lo que allí se vio. El oficio de programar se da por sabido en el nivel del [punto de partida del camino](../00-punto-de-partida.md): editor, terminal, Git y algo de Python o JavaScript. Las páginas de esta etapa no exigen escribir código; el banco de pruebas de la [receta](../../recetas/banco-de-diez-casos.md) sí pide un rato de terminal o una hoja de cálculo.

## Criterio de salida

Elegir un modelo para una tarea propia, justificarlo con una prueba de al menos diez casos, escribir la instrucción que esa tarea necesita y estimar lo que costaría hacerla mil veces. La práctica que cierra la etapa —con su plantilla— se publica con las páginas 4 y 5.

## Páginas

1. [Cómo elegir un modelo para una tarea](01-como-elegir-un-modelo.md) — las cinco variables que deciden, en qué orden se miran, la letra pequeña que dobla la factura y la prueba que zanja la duda.
2. [La instrucción: pedir bien y obtener algo usable](02-la-instruccion.md) — las cinco partes de una instrucción que funciona, qué se fija una vez y qué se pide cada vez, y un antes y un después sobre una tarea aburrida.
3. [El contexto: qué se le da y en qué orden](03-el-contexto.md) — por qué el modelo no recuerda, qué es un presupuesto de tokens, cómo se ordena lo que se le pasa y cuándo conviene empezar de cero.
4. El coste de un uso repetido — *en preparación*.
5. Los límites: cuándo el modelo no es la herramienta — *en preparación*.

## Qué no cubre esta etapa

Recuperación de documentos, memoria persistente, grafos de pasos y evaluación sistemática: eso es la Etapa 2. Patrones agénticos, herramientas y autorreparación: la Etapa 3. Aquí se aprende a usar bien un modelo suelto, que es el 80 % del uso real y la base de todo lo demás.
